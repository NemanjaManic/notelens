## What runs

- FastAPI extraction plus summary at `POST /v1/extract` and document QA at
  `POST /v1/document-answer`; summary stays inside ExtractionResult as an independent
  SummaryOutcome. `GET /health/live` and `GET /health/ready` do not invoke generation.
- A deterministic **mock catalog** recognizes explicit sentence templates. It
  returns literal supported source sentences and conservative evidence states. It is
  not a general-purpose extractor or measured real-model implementation. Unknown
  questions abstain; one demo cough mention is intentionally missed.
- The provider interface, English versioned prompts, request validation, orchestration,
  bounded repair and failure mapping are separate. No provider/model is approved in
  the checkout. Non-mock configuration returns a controlled 503, never a mock fallback.
- The frozen generated Python package validates actual request/response records.
  There are no copied competing API schemas. Exact spans, IDs, hashes,
  citations and source-present ICD checks run separately. Literal generation checks
  and narrow catalog guards are not general semantic-entailment judgments.
- Synthetic reference/prediction evaluation and selection/template/adjudication tools
  run independently of A's RAG, C's classifier and B's frontend.

## Setup and verified commands (Windows, repository root)

Python 3.11.7, Node 24.20.0, local uv 0.13.7 and Promptfoo 0.125.1 were used.
Python 3.13 was proposed in the initial plan but is not installed here. Dependencies
are locked in each owned Python project and eval's package-lock.json. uv is not on
the global PATH; an ignored service-local bootstrap holds it. On a fresh working copy:

```powershell
python -m venv services/extraction/.bootstrap
./services/extraction/.bootstrap/Scripts/python.exe -m pip install uv==0.13.7
./services/extraction/.bootstrap/Scripts/uv.exe sync --locked --directory services/extraction
./services/extraction/.bootstrap/Scripts/uv.exe sync --locked --directory eval
npm.cmd ci --prefix eval --ignore-scripts --no-audit --no-fund
```

The local bootstrap, lock/sync and npm installation were executed. `npm ci` is the
fresh-clone equivalent of the executed lock-producing local npm install. No root
dependencies, lockfiles or operating-system execution policy were changed.

Start the loopback API in one terminal:

```powershell
./services/extraction/.venv/Scripts/python.exe -m notelens_extraction.cli serve
```

Run the synthetic CLI demo, or submit the versioned request fixture:

```powershell
./services/extraction/.venv/Scripts/python.exe -m notelens_extraction.cli demo
./services/extraction/.venv/Scripts/python.exe -m notelens_extraction.cli demo --question "What does the document say about chest pain?"
./services/extraction/.venv/Scripts/python.exe -m notelens_extraction.cli request services/extraction/fixtures/demo-request.json
```

The same fixture can be POSTed from another PowerShell terminal:

```powershell
$requestBody = Get-Content -Raw services/extraction/fixtures/demo-request.json

Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8003/v1/extract -ContentType 'application/json' -Headers @{ 'X-Request-ID' = $requestId } -Body $requestBody
```

The CLI and actual loopback HTTP flow were exercised in the process smoke test.
The Invoke-RestMethod snippet is an equivalent caller example, not separately claimed
as an executed check. The full representative response is generated by the CLI rather
than manually maintaining a second response shape.

Run evaluation and the retained training checker:

```powershell
./eval/.venv/Scripts/python.exe -m notelens_eval.run --profile smoke
./eval/.venv/Scripts/python.exe -m notelens_eval.run --profile smoke --predictions eval/reports/local/predictions.json
python -B docs/extraction-eval/check_training_examples.py
```

The evaluator writes separate predictions, aggregate JSON and a short English report
under ignored `eval/reports/local/`. The profile only accepts synthetic reference
fixtures in this milestone. It passes only requests to generation, never reference
labels; it can also score a separately supplied prediction file. Invalid extraction
records withhold entity metrics instead of silently excluding them. Technical QA
failures are not counted as correct abstention. Exact and relaxed matching are
maximum-cardinality one-to-one, with maximum overlap and stable deterministic ties.
Undefined denominators are null, not perfect scores.

Run Promptfoo against a temporary service which the wrapper starts and stops:

```powershell
./eval/.venv/Scripts/python.exe eval/smoke_http.py
```

The wrapper disables telemetry, sharing, cache and saved Promptfoo evaluations, places
tool metadata under ignored `eval/.promptfoo/`, and only submits synthetic fixtures.
It writes the explicit smoke report under `eval/reports/local/promptfoo.json`.
Promptfoo's Python `call_api(prompt, options, context)` and custom interpreter setting
follow its [provider documentation](https://www.promptfoo.dev/docs/providers/python/).
The installed CLI's `eval --help` confirmed the actual flags. On this restricted
agent host, Node's Windows user-info call needed sandbox escalation; it succeeded
without changing machine policy or using a live model.

## Contract and operational behavior

Inputs and outputs validate against frozen `contracts/v1` (`schema_version: 1.0.0`).
Responses include `Cache-Control: no-store`. Business POSTs require one canonical UUID
`X-Request-ID` and echo it on success/error. Invalid or absent IDs receive 400 with a
fresh diagnostic ID. Health 401 responses use a fresh diagnostic ID and Bearer challenge;
incoming health IDs are ignored. B must bind IDs to session, document/hash and question;
reject expired/stale results before display. D keeps no document store/history/cache.
The service never normalizes or truncates supplied canonical text.

Mock repair permits at most two generation attempts. `X-Generation-Attempts`
exposes the count on successful responses without raw text.
The retry count is an explicit **offline prototype** limit, not an approved live
policy. Structural invalidity triggers bounded repair; outages, rate limits and
timeouts return their own errors. No production timeout/rate/budget capacity is claimed.

Frozen errors: malformed JSON or request ID 400, invalid fields/digest 422, oversized canonical
text 413, configured auth failure 401, malformed generation 502 after bounded repair,
rate limit 429, timeout 504, unavailable provider/configuration 503 and safe unexpected
failure 500. Safe ErrorEnvelope messages omit input bodies and stack traces. PDF handling, common
language detection, browser sessions and expired-document 404 remain B's boundaries.

Set `NOTELENS_SERVICE_TOKEN` server-side to enforce bearer authentication. Without a
token the provided CLI binds to loopback only and the app rejects non-loopback clients.
TestClient's test-only client identity is accepted for in-process checks. Deployment,
TLS, cross-instance state and proxy trust are B-owned future work. HTTP access logs
are disabled by the CLI, and no routine document/provider-body logs are produced.

## Retained behavior and local changes

The staged delta contains 53 D-owned paths. Frozen schemas, generated bindings, other services, web, shared scripts and teammates' annotation paths are byte-identical to main. The staged D service, dependency locks and saved evaluation inputs match the published owner tree. The local differences are the evaluator compatibility fix below and two inherited whitespace cleanups flagged by `git diff --cached --check`.

The reconciliation exposed one evaluator regression. With `NOTELENS_EXTRACTION_MOCK_NOT_READY=1` in the caller environment, `python -m notelens_eval.http_suite` started a deliberately unready service and timed out before its first evaluation request. The three evaluation launchers now drop that flag from the environment of their own healthy mock subprocess. The existing readiness integration test exercises the inherited flag. The D service still honors the flag when launched directly for B's checker.

- Prepared document identity and SHA-256 pass through unchanged. D's extraction checks exact quote slices at half-open Unicode code-point offsets, including repeated and non-BMP text, and keeps assertion, temporality and subject as distinct fields.
- Extraction and summary outcomes remain independent. Document answers keep supported claims and document source links on partial outcomes. RAG retains separate literature claims and provenance. The accepted web shell uses fixture-backed behavior, so real mixed routing remains a B decision.
- D checks canonical business request ID admission before auth, rejects duplicate authorization headers and uses fresh IDs for health diagnostics. The D readiness trigger `NOTELENS_MODE=mock` with `NOTELENS_EXTRACTION_MOCK_NOT_READY=1` yields readiness HTTP 503 with `status=not_ready`, `mode=mock` and `reason=mock_not_ready`, while liveness remains HTTP 200 with `status=alive`.
